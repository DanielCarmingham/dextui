# dexrust Rename Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the Rust Dex implementation to `dexrust` across source, packaging, releases, Homebrew, and dextui while retaining `dex` as a compatibility executable.

**Architecture:** First make and verify the complete source/package rename in the existing `dexrs` checkout, with the primary `dexrust` and compatibility `dex` binaries calling one shared `dexrust` library. Then prepare downstream dextui documentation. Only after all local work is reviewable do the gated publication steps rename GitHub, publish `dexrust` 0.2.0, verify every install route, update dextui, yank `dex-cli`, and delete its old Homebrew formula.

**Tech Stack:** Rust 2024, Cargo, clap, cargo-dist 0.32, cargo-binstall metadata, GitHub CLI, crates.io, Homebrew, dex, GitNexus/CodeGraph.

**Spec:** `docs/superpowers/specs/2026-10-02-dexrust-rename-design.md`

## Global Constraints

- The public repository, Cargo package, Rust library crate, Homebrew formula, release prefix, shell installer, and primary executable must all be named `dexrust`.
- Continue shipping `dex`; it must execute the same code and identify itself as `dexrust v<version>`.
- Do not ship a `dexrs` executable from `dexrust`.
- Keep `.dex`, Dex configuration paths, `DEX_*` environment variables, JSONL formats, sync metadata, and MCP protocol compatible.
- The first `dexrust` release is `0.2.0`; Rust remains at version 1.88 or newer.
- Do not publish another `dex-cli` version. Yank `0.1.1` and `0.1.2` only after `dexrust` and downstream instructions are verified.
- Do not retain a `dex-cli` Homebrew alias or compatibility formula.
- Use LF line endings for every shell or workflow file.
- Run CodeGraph exploration and impact analysis before editing symbols in repositories that provide a `.codegraph/` index.
- Run GitNexus `detect_changes --scope compare --base-ref main` before committing in dextui.
- Do not place dex task IDs in commits, documentation, release notes, or pull requests.

## Review Focus

- Invoking either installed binary as `dexrust version`, `dex version`, `dexrust --version`, or `dex --version` must report `dexrust v0.2.0`; Task 1 adds direct assertions for all combinations.
- Shell completion output must use the actual invoked executable name (`dexrust` or `dex`) and must never emit `dexrs`; Task 1 expands the completion test.
- Renaming the package must not rename `.dex`, `DEX_HOME`, `DEX_STORAGE_PATH`, config paths, JSONL fields, or MCP server compatibility identifiers; Task 2 runs focused compatibility tests and a forbidden-diff search.
- `cargo binstall dexrust` must download the versionless cargo-dist archive instead of silently compiling; Task 3 validates `pkg-url`, archive format, binary directory, and the published install path.
- A partial external release must leave a usable recovery path: do not yank `dex-cli` or delete its formula until Cargo, shell, Homebrew, cargo-binstall, and dextui verification all pass; Tasks 5 and 6 enforce this order.
